# 0004 — Phase 3 generation grading and acceptance

Status: accepted, 2026-09-18.

Context: Phase 3 generation and trusted citation resolution are verified. The fixed dataset has 31 answerable cases with 71 expected answer points. The dense baseline retrieves all annotated sources for 17 answerable cases, some for 6, and none for 8; answerable-case Recall@5 is `0.6344086021505375`. Generation therefore needs separate gold-evidence and retrieved-evidence views.

Decision: use a hybrid local grader. Deterministic code validates execution, seller isolation, citation IDs and exact source metadata. Ollama `qwen2.5:7b-instruct-q4_K_M` grades semantic faithfulness, relevance, answer-point availability/completeness and whether cited evidence supports the answer, returning schema-constrained JSON. One judge call grades all semantic dimensions for one output. The judge is calibrated against 20 versioned, human-authored positive/negative examples drawn from 10 stratified answerable cases; acceptance requires at least 90% exact label agreement and Cohen's kappa at least 0.80.

The generation evaluator runs all 31 answerable cases twice: annotated gold evidence and actual top-five retrieval evidence, producing 62 generator calls and 62 consolidated judge calls. All 40 fixed cases still run through dataset/retrieval gates; Phase 4 owns abstention quality for the 9 unanswerable cases.

Hard failures in either view are any unsupported confident policy claim, cross-seller evidence, unknown/invalid citation, evaluation error or skipped case. Gold-evidence thresholds are: 31/31 faithful, 31/31 citation-correct, relevance at least 30/31, and completeness at least 64/71 expected answer points. Retrieved-evidence thresholds are: 31/31 faithful, 31/31 citation-correct, relevance at least 27/31, conditional completeness at least 90% of answer points the judge finds present in retrieved evidence, and raw completeness at least 40/71. Numeric, time, fee and exclusion claims remain subject to the zero-unsupported-claim hard gate.

Reports record Ollama/runtime/model artifact identities, prompts/schemas/options, per-case judgments, all durations and token counts exposed by Ollama, error rate and zero local per-request cost. Latency is measured but is not a Phase 3 quality gate until a hardware-specific service-level objective is approved. A fresh real-service run is mandatory for the generation gate; fake transports remain test-only. Regression and system gates validate the pinned generation report and reuse a matching fresh report when available rather than multiplying model calls.

Alternatives: using the 1.5B generator as its own judge was rejected as too circular. Cloud grading was rejected because it adds credentials, cost and policy-data transfer. Fully deterministic semantic matching was rejected because paraphrases make it too brittle. A larger local judge increases disk and runtime cost but keeps evidence local and separates generation from grading capacity.

Consequences: the selected judge adds an approximately 4.7 GB local model and makes a complete run 144 model calls including calibration. The first passing report becomes the Phase 3 pinned baseline. Any judge, prompt, schema, threshold, corpus or dataset change requires a new recorded decision and fresh baseline rather than silently reusing evidence.

Runtime amendment, 2026-09-18: the complete implementation performs 62 generator calls, 62 main judge calls and 20 calibration judge calls, or 144 total. A real CPU-local run exceeded the original 900-second gate budget while still progressing. Human review approved 1800 seconds for the generation, regression and system gates without changing the workload, models or quality thresholds. Other gate timeouts remain unchanged.

Judge amendment, 2026-09-18: human review approved replacing the overloaded consolidated semantic judgment after it produced false unsupported labels on plainly supported real answers. The same local 7B judge now performs two atomic judgments: sentence support against cited evidence, then answer-point availability and coverage against all supplied evidence. Deterministic code derives faithfulness and citation correctness from sentence support and continues to enforce seller/citation identity.

Calibration expands to 62 fixed representative examples covering every answerable case: one fully supported answer and one partial answer with a human-authored near-policy error per case. Forty-two examples form the prompt-tuning partition and 20 remain holdout. Both overall and holdout calibration retain the 90% agreement and kappa 0.80 floors; unsupported precision must be at least 95%, unsupported recall at least 90%, and no supported calibration sentence may be falsely marked unsupported. The generation-quality thresholds do not change.

Implementation outcome, 2026-09-18: after three bounded calibration attempts, homogeneous schema-bounded batching completed all 62 examples in 19 judge calls but failed the accepted floors. Overall agreement was `0.8830897703549061`, kappa `0.4690629824630858`, unsupported precision `0.8333333333333334`, unsupported recall `0.4838709677419355`, and three supported sentences were falsely rejected. The 20-example holdout reached agreement `0.8866666666666667`, kappa `0.5201354911554386`, precision `1.0`, recall `0.7`, and zero false unsupported labels. The task is blocked: the approved 7B judge is not accepted for this policy-entailment workload, and choosing a different judge is a new decision.
